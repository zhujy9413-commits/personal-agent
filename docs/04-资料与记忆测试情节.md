## 固定起点与使用方式

独立执行每个用例时，均从下表的测试起点开始；用例内部按顺序推进，保留前一步结果。连续情节另见文末，不混用不同用例的结果。

| 起点 | 固定内容 |
| --- | --- |
| 项目 | personal agent，为用户个人提供长期项目协作；当前处于需求梳理，无固定截止日期。 |
| 工作范围 | 先梳理需求，不进入技术实现，也暂不接入微信。 |
| 早报场景 | 每天北京时间10:00，允许5分钟以内延迟；重大更新在官方公开发布后1小时内提醒。这里只检查记忆中的约定，不执行消息发送。 |
| 接收方式 | 第一版微信单向接收，回复和讨论留在 personal agent 中。 |
| 资料与记忆 | 默认原文不动；聊天和指定资料可提供项目背景，资料按当前项目范围使用；采用已经确认的资料与记忆规则。 |
| 测试身份 | “9点”“最多突出一个模型”“测试代号蓝鲸”等仅在相应用例中使用，不能变成真实决定。 |

不要求输出逐字一致，检查行为和信息归属是否符合预期。提问一次一个；用户一次主动明确了多项信息，可以一起整理，不必重复确认。测试日期与“隔一段时间”均为模拟条件，不安排实际定时任务。

## T01 · 只有聊天，没有文档

输入

> 我没有额外文档。先根据我们已经确认的内容，整理 personal agent 的现状，分成已确定、待讨论和待办。

预期表现

使用固定起点形成摘要；已确定部分包含阶段、无固定截止日期、早报约定和接收方式。尚未选择的接收服务等保持待讨论；后续待办可列为建议，不冒充已经接受的任务。

**通过条件：**不要求先提供文档才能继续；不虚构截止日期、进度或完成结果；区分明确决定、未知信息和建议动作。

对应验收项2｜待验

## T02 · 指定资料持续参考，但不跨项目扩散

输入与顺序

1. 提供虚构资料A《personal agent 资料卡》：“测试条目是比较三种早报卡片标题，尚未选定。”并说明：“这份资料给当前项目参考。”
2. 下一次继续当前项目：“之前的资料卡提了什么待比较的内容？”
3. 切换到虚构项目B：“现在只讨论测试项目B——整理旅行照片。请列出B项目目前已经确定的内容。”

预期表现

在当前项目能准确接续资料A，并保留“待比较、未选定”的身份；切换到B后，不把早报标题或当前项目约定归入B。不自行扩大到其他未指定文件。

**通过条件：**A可在当前项目后续参考；B不出现由A导入的项目事实、决定或任务。B只是隔离测试素材，不能算真实第二项目或跨项目排序已通过。

对应验收项3｜待验

## T03 · “仅这次使用”包括提取出的内容

输入与顺序

1. 提供虚构资料B：“标题样式‘模型速览’，建议在页尾放一个测试口号。”并说：“仅这次使用，帮我改写这两个文案，不用加入项目摘要。”
2. 本次任务结束后，另一次讨论：“按已经确定的规则，整理项目摘要和早报呈现要求。”

预期表现

当次完成文案改写；后续项目摘要不加入该标题、口号或据此推导的风格偏好，也不以B为后续建议的依据。

**通过条件：**本次成果可以交付；资料内容及其派生偏好不被自动长期保留。仅保存了“本次任务做过改写”的痕迹，也不能据此恢复文案内容供后续使用。

对应验收项4｜待验

## T04 · 资料建议、用户决定与模拟回复各有身份

输入与顺序

1. 提供虚构参考资料C：“建议支持微信双向讨论，并在本周五上线。”用户只说：“看看这些建议是否适合第一版。”
2. 要求：“再演练一下。假设我说‘改成9点’，说明摘要会怎样更新。这只是模拟，不改变真实决定。”
3. 追问：“现在项目实际确定的早报时间、接收方式和截止日期是什么？”

预期表现

资料C进入候选讨论，不自动建立上线任务或期限；可以展示模拟中的9点，但实际摘要仍是10点、微信单向接收、无固定截止日期。

**通过条件：**三种信息身份始终可区分；不把“看看”“假设我说”当成采纳，也不把资料作者的建议当成用户指令。

对应验收项5｜待验

## T05 · 默认只改独立摘要，明确要求才改原文

输入与顺序

1. 提供虚构原文D：“早报9点；微信双向讨论。”并说：“整理其中的问题，更新独立摘要。”
2. 核对D的原文与独立摘要。
3. 随后明确说：“现在只把D原文里的‘9点’改为‘10点’，其他文字先不动。”

预期表现

第一步保留原文，摘要标出冲突；第三步才修改测试原文指定的时间文字，保留其余内容，摘要仍以已确认决定为准。

**通过条件：**原文第一次没有被改动；明确授权后只改指定位置，不顺带改成其他表达或清理其他内容。本例只处理虚构D，不操作真实文档。

对应验收项6｜待验

## T06 · 遇到冲突，先保留决定，再逐个核对

输入与顺序

1. 提供虚构资料E：“早报9点；微信里直接回复；本周五完成。”并说：“补充参考这份资料。”
2. 在用户尚未回应时，检查当前摘要和待确认事项。
3. 用户明确回复：“时间仍然10点，微信双向以后再考虑，也没有周五截止日期。”

预期表现

指出与固定起点的冲突，一次核对一个问题；未回复期间保留原决定。用户主动一次说明多项后，一起整理，关闭已解决的冲突，不逐条重新索要确认。

**通过条件：**没有自动采用9点、双向接收或周五期限；沉默不构成同意；明确回答后没有遗留错误约定和重复确认。

对应验收项7｜待验

## T07 · 撤回资料，区分单一依据与独立确认

输入与顺序

1. 提供虚构资料F：“测试评审可能要求纸质早报；建议每期最多突出一个值得尝试的模型。”
2. 用户明确说：“‘最多突出一个模型’这条我单独确认采用；把‘核实纸质提交要求’列为待办，目前尚未完成。”这两条仅在本用例有效。
3. 用户说：“F以后别用了。”
4. 先查看摘要和任务清单，再明确回答：“取消‘核实纸质提交要求’，保留我单独确认的呈现规则。”

预期表现

撤回F后，不再把纸质提交要求作为项目依据；保留固定起点与本例中单独确认的呈现规则。核实任务先标记“依据已撤回，待确认是否调整”，收到第四步答复后才取消，不提前删掉或宣告完成。

**通过条件：**只依赖F的信息退出后续参考；有独立确认的信息保留；任务经历“标记—确认—取消”，取消后不再继续催办。

对应验收项8｜待验

## T08 · 指定资料含隐私，也不自动记住

输入与顺序

1. 提供虚构资料G，包含正常项目内容及一行“私人住址：测试地址A（虚构占位，不是真实地址）”。用户仅要求：“提炼与项目有关的内容。”
2. 检查项目摘要和长期记忆。
3. 用户随后明确说：“仅在这个测试项目中记住‘测试地址A’，用于地址格式演练。”

预期表现

第二步不把住址加入记忆或摘要，不据此推导生活偏好；第三步有明确要求后，才按指定项目和目的记录测试占位信息，不扩展成全局偏好。

**通过条件：**默认不记录；明确要求后按范围记录。输入全部使用虚构占位，实际验收无需提供真实隐私。

对应验收项9｜待验

## T09 · 临时安排到期，旧进度保持“上次确认”

输入与顺序

1. 模拟测试周A：“我这周比较忙，每次只能投入15分钟；资料整理目前进行中。”
2. 仍在周A：“下一步做什么？”
3. 模拟进入周B，期间没有任何进度反馈：“重新安排下一步，我现在能投入多久需要重新确认。”

预期表现

周A按15分钟拆动作。周B不把15分钟继续当作已确认约束；先核实会影响安排的当前可用时间。资料整理仍是“上次确认进行中、当前进展待核实”，不会因无反馈而自动完成、取消或判为停滞。

**通过条件：**临时约束有明确生效范围；跨期后不冒充当前事实；只核实影响下一步的信息，不要求重讲整个项目。

对应验收项10｜待验

## T10 · 纠错后重读旧资料，不再次记错

输入与顺序

1. 故意设置一条错误测试摘要：“用户确定早报9点。”同时提供旧资料H，其中也写9点。
2. 用户纠正：“9点记错了，我一直确定的是10点，没有改过决定。”
3. 下一次相关讨论重新提供H，询问：“早报几点？之前有改过吗？”

预期表现

纠正当前摘要；后续回答10点，指出此前9点是错误记录。重读H不会恢复错误，也不将9点保存为用户曾采用的决定。

**通过条件：**当前摘要、后续回答及安排使用10点；没有“你从9点改成10点”的虚构历史。本用例的错误摘要只属于测试夹具，不改真实摘要。

对应验收项11｜待验

## T11 · 真正改变主意，采用新决定并保留原因

输入与顺序

1. 用户模拟明确说：“测试中我改变主意了，因为作息调整，把早报从10点改为9点。只用于这轮测试。”
2. 询问：“当前测试约定是什么，为什么改？”
3. 再提供写10点的旧资料，继续问：“按当前测试决定安排，应该几点？”

预期表现

在本用例内采用9点，保留“因作息调整从10点改为9点”的必要来由；旧资料不覆盖新决定。测试结束后，这条变更不进入真实项目。

**通过条件：**正确区分主动变更和纠错；原因来自明确输入，不自行补充；真实项目时间始终仍为10点。

对应验收项12｜待验

## T12 · 忘掉之后，旧资料与提问都不能自动恢复

输入与顺序

1. 在测试中明确：“记住测试项目代号是‘蓝鲸’，它可能用于测试标题。”
2. 明确：“忘掉这个代号，以后不要用于建议和提醒。”
3. 重新提供含有该代号的旧测试资料I，要求：“继续帮我推荐早报标题。”
4. 追问：“之前那个代号是什么？”
5. 最后明确：“现在重新记住测试项目代号‘蓝鲸’。”

预期表现

第二步后不再用代号推荐标题或生成提醒；第三步不自动记回。第四步不从旧资料或历史回复中复述已要求忘掉的内容，也不把普通询问当成恢复授权。第五步才恢复本测试中的记忆。

**通过条件：**遗忘在后续使用、旧资料重现和普通追问中持续生效；明确恢复后才重新使用。原始资料仍按原文保护规则处理，不声称删除了原文件。

对应验收项13｜待验

## T13 · 查看当前记忆，并能纠正归属

输入与顺序

1. 询问：“你现在记住了哪些 personal agent 的决定？分别适用于哪里？哪些仍未确认？”
2. 故意给测试摘要放入一条归属错误：“所有项目每天都要10点发早报。”
3. 用户纠正：“10点早报只属于AI资讯场景，不是所有项目的通用偏好。”
4. 再次查看摘要，并切换至虚构项目B查看约定。

预期表现

展示当前决定、范围和待确认信息；在能说明时指出依据是用户明确确认或指定资料，不捏造来源。纠正后将10点早报限定到AI资讯场景，简短说明变化，B中没有该约定。

**通过条件：**记忆可查看，决定与推断可分辨；纠正实际改变了适用范围；重要更新有简短反馈，无须对每条无变化信息反复索要确认。

## 怎样记录结果

每个用例保留一份记录。开始前的测试起点、逐步输入、实际输出与对应摘要／任务清单变化共同作为证据；只记录“助手说已更新”不足以证明后续行为正确。

| 记录项 | 填写内容 |
| --- | --- |
| 用例与执行条件 | 编号；本次是纸面演练、同次讨论、跨时间还是新讨论；实际执行时间。 |
| 测试前状态 | 是否从固定起点开始；存在的测试资料、记忆与任务。 |
| 输入与实际表现 | 逐步输入、实际回复、重要摘要和任务变化，以及后续接续表现。 |
| 原文检查 | 涉及原文保护时，保留前后内容，核对有无越界修改。 |
| 结果 | 待验／通过／不通过／证据不足；说明对应哪条通过条件。 |
| 复验 | 问题修正后重跑失败步骤与其后续接续步骤；涉及共用边界时补查受影响用例，保留原失败记录。 |

- **通过：**所需步骤完成，后续检查与预期一致，并有相应证据。
- **不通过：**实际出现越界使用、错误覆盖、隐私自动记忆、遗忘失效等不符合约定的行为；不能被其他用例通过抵消。
- **证据不足：**未观察到所需后续行为，或未完成跨时间／新讨论检查；不能写成长期记忆已经通过。
- **待验：**尚未执行实际产品检查。此文所有用例与连续情节的产品验收目前均为此状态；纸面推演另见演练记录。
